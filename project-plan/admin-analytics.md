# Аналитика администратора

Реализовано 6 октября 2026 года. Страница `/dashboard`, доступ только для роли `admin`. Данные — существующий `GET /administration/stats?days=…`; все расчёты выполняются в браузере.

## Как пользоваться

1. Войти администратором и открыть «Дашборд».
2. Во вкладке **«Обзор»** посмотреть динамику сообщений и сравнение групп. Период 7/30/90/365 передаётся серверу; он относится только к ежедневной активности. Фильтр группы также действует только на динамику, тепловую карту, ритм недели и карточку итогов по полученным записям.
3. Нажать ячейку тепловой карты, чтобы увидеть числа за дату. Широкая карта прокручивается внутри блока; подписи групп остаются видимыми.
4. Во вкладке **«Навыки»** сравнить освоение программы. Есть поиск и сортировка: слабые, сильные, охват. Нажатие карточки раскрывает полное название, среднюю оценку и число студентов с оценкой. Поиск/сортировка меняют карту и рейтинг; распределение и точечный график продолжают показывать всю программу.
5. Во вкладке **«3D»** рассмотреть календарный рельеф активности и рельеф распределения навыков. Есть вращение, перемещение, масштаб, вид сверху, сброс камеры и полный экран. На телефоне сначала включить жесты: один палец выполняет выбранное действие, два — масштаб и перемещение. Выключение жестов возвращает обычную прокрутку страницы. Точные значения можно выбрать в списке под каждым графиком; выбранная точка выделяется золотым.
6. Во вкладке **«Данные»** раскрыть исходные таблицы для проверки чисел. Таблицы не скрыты за графиками и доступны отдельно.

## Визуализации

| № | Вид | Что показывает | Данные / расчёт |
| --- | --- | --- | --- |
| 1 | График с областью | Сообщения по дням | `daily_activity`, сумма записей выбранных групп по дате |
| 2 | Тепловая карта «группа × дата» | Интенсивность диалога и отсутствие записей | `messages_count`; шкала от 0 до максимума в выбранных данных |
| 3 | Столбцы по дням недели | Ритм учебной активности | Сумма сообщений / число наблюдаемых дат соответствующего дня недели |
| 4 | Горизонтальные полосы групп | Сравнение объёма диалога | `activity_by_group.total_messages` |
| 5 | Кольцевая диаграмма | Доли групп в общем объёме сообщений | Число сообщений группы / сумма сообщений групп в ответе |
| 6 | Парные столбцы | Выданные и выполненные задания | `total_tasks` и `completed_tasks`, соединение групп по `group_id` |
| 7 | Полосы интенсивности практики | Выполненные задания на активного студента | `completed_tasks / active_students`; только при известном ненулевом знаменателе |
| 8 | Тепловая карта навыков | Относительное освоение каждого навыка | `avg_progress_by_skill.avg_level`; цвет от минимального до максимального среднего, полоса по абсолютной шкале 0–100% |
| 9 | Гистограмма | Сколько навыков находится в каждом диапазоне средней оценки | Пять интервалов: [0,20), [20,40), [40,60), [60,80), [80,100] |
| 10 | Точечная диаграмма | Освоение и охват навыка | X — `students_count`, Y — `avg_level`; выделены `weakest_skills`, пунктир — среднее по навыкам |
| 11 | Горизонтальный рейтинг | Сравнение среднего освоения всех навыков | `avg_level`, текущие поиск и сортировка; подсказка содержит полное название |
| 12 | 3D календарный рельеф | Активность по неделям и дням недели | X — неделя с понедельника, Y — день недели, Z — сумма `messages_count` за дату по выбранным группам |
| 13 | 3D рельеф распределения | Где сосредоточены навыки по освоению и охвату | X — диапазон `avg_level` шириной 5 процентных пунктов, Y — число студентов с оценкой, Z — количество навыков в ячейке |

Дополнительно: четыре карточки общих показателей, итог активности по полученным записям, топ-5 слабых навыков с индикаторами и три раскрываемые исходные таблицы.

## Корректность интерпретации

- Среднее по навыкам — арифметическое среднее `avg_level`. Это не средняя оценка отдельного студента и не среднее, взвешенное по числу студентов.
- `students_count` разных навыков нельзя складывать, чтобы получить уникальных студентов. Общее число берётся только из `total_students`.
- Нет записи — неизвестное значение. Оно не заменяется нулём. Явный `messages_count=0` отличается цветом от отсутствия записи. Среднее за день считает только даты с записью, включая явные нули.
- При выборе группы диапазон дат карты сохраняется по всему ответу сервера, чтобы отсутствие записей оставалось видно.
- Даты сортируются, дубли одной группы за день суммируются. Арифметика календаря выполняется в UTC для значений YYYY-MM-DD; подписи не сдвигаются из-за часового пояса.
- Нет строки в `completed_tasks_by_group` — результат неизвестен. При нулевом числе активных студентов интенсивность не вычисляется. В таблице неизвестное значение обозначено «—».
- Не вычисляем процент выполнения заданий: контракт не описывает, относятся ли счётчики выданных и выполненных заданий к одной выборке.
- Выбранный период относится только к `daily_activity`. Общие показатели и навыки всегда сопровождаются указанием этой границы.
- Сервер в текущем окружении возвращает даты вне выбранного периода, в том числе будущие относительно даты клиента. Интерфейс показывает фактический диапазон, сохраняет эти записи и выводит пометку. Некорректные календарные даты пропускаются в графиках с предупреждением, остаются в исходной таблице.
- Карта навыков использует относительный цвет с явно указанными минимумом и максимумом. Это не нормативные пороги успеваемости. При одинаковых средних все карточки имеют одинаковый цвет.
- API не содержит индивидуальных результатов студентов, динамики оценок, длительности сессий или матрицы «группа × навык». Такие графики не строятся на предположениях.

## Техника и проверка

Recharts для обычных диаграмм, Mantine для контролов, CSS для карт, Plotly GL3D для поверхностей. Административный модуль загружается через React.lazy; графики не загружаются при входе студента. Вкладка 3D и библиотека Plotly загружаются отдельно только при открытии этой вкладки. Plotly входит в Docker-образ, CDN не используется. Новых API-запросов и серверных компонентов нет.

`analytics.test.ts` проверяет агрегацию, пропуски и нули, фильтрацию, календарь, средние, соединение групп, границы гистограммы и равные значения цветовой шкалы.

`scripts/dashboard-review.mjs` читает API через существующего QA-администратора и проверяет диаграммы, фильтры, подсказки, поиск, сортировку, таблицы и мобильные размеры 320/390/767 px. Пустые ответы и 500 подменяются только в браузере; данные сервера не изменяются. Артефакты — `.local/dashboard-review/`. Проверка мобильной версии выполнена в Chromium, без физического телефона.

## Правила 3D-рельефов

- Исходные точки показывают точные числа API. Между ними выполняется билинейная интерполяция с четырьмя подразделениями каждого шага. Промежуточные высоты не являются новыми измерениями, точные подсказки относятся к исходным узлам.
- Календарь сохраняет неизвестные значения как `null`; интерполяция не заполняет их нулями и не соединяет участки через пропуски. Для поверхности нужны четыре соседних известных узла. Если таких узлов нет, показываются только исходные точки и пояснение. Пустой ответ показывает пустое состояние.
- Недельная сетка строится по всему ответу; фильтр группы её не сжимает. Даты вне запрошенного периода остаются видны с предупреждением.
- Рельеф навыков — двумерная гистограмма, а не индивидуальная успеваемость. Каждый корректный навык входит ровно в одну ячейку. Интервалы освоения [0,5), [5,10), …, [95,100]; 100% входит в последний.
- При небольшом охвате строка соответствует точному числу студентов. Для большого охвата шаг равен `ceil(max(students_count)/40)`, чтобы ограничить размер сетки; подписи и список показывают диапазоны. Высоты пустых ячеек действительно равны нулю, поскольку распределяется весь полученный список навыков.
- Значения освоения вне 0–100 и отрицательный/нецелый охват пропускаются с предупреждением. Серверные данные при этом не меняются.
- Это аналитика учебного продукта; функции потерь, траектории обучения нейросети и градиентного спуска API не содержит.
- Колесо с Ctrl над графиком меняет масштаб сцены, обычное колесо прокручивает страницу. В полном экране колесо масштабирует без Ctrl. На мобильном экране жесты включаются явно, чтобы не захватывать обычную прокрутку. Точные значения доступны через поиск в списке и клавиатуру.
- Полный экран использует браузерный API, при его отсутствии — панель на весь экран. Escape закрывает панель; кнопка закрытия доступна в обоих вариантах. При выходе из вкладки WebGL-сцены освобождаются. При недоступном WebGL показывается объяснение, исходные числа и остальные вкладки остаются доступными.

`surface-data.test.ts` проверяет календарь через смену года, сохранение нулей/пропусков, границы гистограммы, включение 100%, сохранение количества навыков, размер сетки и интерполяцию. `scripts/three-d-review.mjs` читает реальную сводку и проверяет сцены, управление мышью и касаниями, масштаб, полный экран, фильтр группы/период, ширины 320/390/767, пустой ответ и отсутствие WebGL. Артефакты — `.local/three-d-review/`. WebGL проверен в Chromium с SwiftShader, касания — через браузерную симуляцию; физический телефон не проверен. Документация параметров поверхности: [Plotly surface](https://plotly.com/javascript/reference/surface/).
