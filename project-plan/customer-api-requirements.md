Новый Swagger принят. Дашборд, роли, серия дней, слабые места и структурированная оценка доступны. Проверили сервер: выдали задание тестовому студенту, получили оценку, обновление прогресса и серии. Остались следующие изменения.

## Для интеграционной приёмки

1. **GET /task/current должен возвращать исходный текст активного задания и null после завершения.** Сейчас после ответа возвращается последняя реплика ментора, а после task_completed=true тот же ID остаётся «активным». Пример: студент ID 34, question_id=bc8419f3-6721-48c6-bab0-48b01c2b6d17. Если завершённое задание предполагается возвращать, добавьте явный status. Закрепите также поведение предыдущего задания при новом POST /task.
2. **Исправить порядок /chat/history.** У этого студента 1390_ai стоит перед 1390_user, хотя пользовательское сообщение раньше; аналогично 1391_ai/1391_user. Последние N сообщений должны идти от старых к новым, включая служебные записи с timestamp=null. Для равных времён нужен стабильный порядок создания.
3. **Добавить часовой пояс timestamp.** Приходит, например, 2026-10-05T17:20:05.818336. Для OpenAPI date-time нужен Z или смещение. Укажите часовой пояс и границу дня для серии и ежедневной статистики.

### Дополнение: новый студент группы 2020tt2 не может начать обучение

После отправки первоначального запроса пользователь сообщил об ошибке создания задания. Проблема воспроизведена 5 октября в 18:07 UTC на отдельном QA-студенте ID 38, зарегистрированном с group_id=2. `/me` показывает группу `2020tt2` (в `/groups` тот же ID подписан `7tt2`).

- `GET /skills` → 200, `[]`.
- `GET /progress` → 200, `[]`; для нового студента отсутствие оценок ожидаемо.
- `POST /task` без тела → 500, `{"error":"Внутренняя ошибка сервера. Попробуйте позже."}`. Одинаково через наш Docker-прокси и напрямую к API.
- Для сравнения: новый QA-студент ID 36 в группе `2026ии1` получает 27 навыков и задание со статусом 200.

**Просьба:** проверить связь группы `2020tt2` с курсом/специальностью и наличие её матрицы навыков, обеспечить выдачу заданий для группы. Если обучение для этой группы пока не настроено, вернуть документированный 503 «Нет доступных навыков для генерации задания», а не 500, и исключить неподготовленную группу из доступных для регистрации либо явно сообщить о её состоянии. Уточнить также различие названий группы в `/groups` и `/me`.

Отсутствие навыков подтверждено ответом API; точная внутренняя причина 500 требует логов сервера заказчика. Повторная проверка: `node scripts/check-task-availability.mjs 2`; ожидаются непустой каталог и успешная выдача задания после подготовки группы. Доступ QA хранится локально, в запрос заказчику не включается.

## Перед публичным выпуском

4. **Запретить анонимное назначение admin и teacher через /register.** Запрос role=admin сейчас успешно создаёт администратора с доступом ко всей статистике. Выбор роли во фронтенде не защищает API. Публичная регистрация должна создавать студента; повышенные роли назначаются доверенным оператором или защищённым методом.
5. **Предоставить HTTPS-адрес API.** Сейчас указан http://ai-mentor.tw1.ru:8000. HTTPS на фронтенде не защищает участок от прокси до HTTP API, по которому передаются пароль и Bearer-токен.
