# Интерфейс: уточнение учебного сценария

5 октября 2026 года. Вопросы к заказчику отложены по просьбе пользователя; этот этап относится к интерфейсу существующего клиента.

## Что было непонятно

| Место | Изменение |
| --- | --- |
| Новый студент не понимает, с чего начать | Блок практики: получить задачу, написать ответ, получить оценку; пояснение автоматического выбора навыка |
| Неясно, что писать в пустой чат | Примеры вопросов заполняют черновик без отправки; отдельно объяснён свободный разговор |
| Переключатель связи с заданием не объясняет режим | Два режима «Ответ на задание» и «Вопрос ментору», с пояснением перед полем |
| Длинное задание отодвигает поле ответа за первый экран | На широком экране задание слева, чат справа; на телефоне чат занимает экран, задание открывается отдельно |
| Начальный экран навыков кажется пустым | При отсутствии оценок сначала открывается каталог. Разные сообщения для отсутствия программы и отсутствия результатов |
| Ответы AI показывают символы Markdown | Заголовки, списки, выделения и код отображаются через react-markdown; сообщения студента остаются обычным текстом |
| В интерфейсе видны служебные подробности | ID задания убран с основной карточки; пояснения формулируются через действия студента |

## Визуальное направление

Сдержанный учебный кабинет: ровный серый фон, белые поверхности, тонкие границы, скругления 6–8 px, один синий акцент. Градиенты и большая тень формы входа убраны. Навигация отмечает текущую страницу спокойной подложкой; заголовки, кнопки и подписи используют общую тему Mantine. Логотип — простая иконка учебника.

Цветные статусы сохраняются для результата, ошибки и предупреждения. Обычные пояснения отображаются текстом, чтобы не конкурировать с основным действием.

## Поведение

- Получение задания выполняется только по кнопке. При уже выданном задании требуется подтверждение замены в интерфейсе.
- Новое задание автоматически включает режим ответа. Переключение на свободный вопрос сохраняет черновик и отправляет question_id=null.
- Примеры вопросов только заполняют поле; пользователь сам нажимает «Отправить».
- После оценки показываются подтверждённые данные сервера и ссылка на прогресс.
- Каталог показывает темы программы, без фиктивной возможности выбора навыка для выдачи.
- Ошибка выдачи предлагает проверить текущее задание и продолжить свободный диалог. Программа и результаты не подменяются демонстрационными данными.

## Проверка

Проходят typecheck, production-сборка и 15 unit/DOM-тестов. Проверяется сохранение черновика и режима при навигации, возврат из задания, переход от выдачи к ответу, отправка свободного вопроса без question_id и отсутствие автоматической отправки примера.

`scripts/ui-review.mjs` использует уже созданные QA-аккаунты и читает работающий API. Проверяет начальный экран, оба режима, видимость поля на десктопе, раскрытие задания на телефоне, начальную вкладку каталога, пустые состояния, дашборд и отсутствие переполнения/исключений. Снимки и отчёт — в игнорируемой `.local/ui-review/`.

На первом варианте прошли 17 проверок ui-review и 14 проверок browser-smoke, включая вход/выход, разграничение доступа и очистку сеанса по реальному 401. Снимки десктопа и телефона просмотрены после добавления форматирования текста.

## Мобильный сценарий после замечаний пользователя

Чат — основной экран. Никакой постоянной карточки получения задания над перепиской: компактная кнопка «Задание» находится в верхней панели. В пустом диалоге есть дополнительная кнопка «Начать практику».

Задание открывается отдельным экраном в том же разделе (`/chat?view=task`). Это позволяет прочитать длинный текст, не закрывая переписку; системная кнопка «Назад» возвращает в чат. Внизу экрана задания закреплена кнопка «Ответить в чате», до выдачи — «Вернуться в чат». Получение выполняется только по кнопке на этом экране, затем студент сначала видит текст и сам переходит к ответу. Модальное окно используется только для подтверждения замены уже выданного задания.

Нижняя навигация студента: «Чат / Навыки / Профиль». У администратора — «Дашборд / Профиль»; пункты соответствуют доступу роли. Гамбургер на телефоне убран. Контент остальных страниц учитывает высоту навигации и безопасные области экрана.

В чате прокручивается только история; поле и кнопка отправки остаются доступными. Высота учитывает visualViewport; когда клавиатура уменьшает доступную область, нижняя навигация скрывается. Черновик и выбранный режим сохраняются в sessionStorage по студенту, режим дополнительно привязан к ID задания. Выдача нового задания включает режим ответа, завершение очищает связь. Результат доступен из компактной кнопки в чате, подробности — на экране задания.

Проверяются размеры 320×568, 390×844, 430×932, 767×844 и 390×430: отсутствие прокрутки всей страницы чата и горизонтального переполнения, доступность поля и достаточная область истории. Уменьшение visualViewport под клавиатуру проверяется симуляцией в Chromium; это не проверка физического телефона. Навигация и чтение задания проверяются на существующих QA-аккаунтах. Успешная выдача в браузерной проверке подменяется локальным ответом API и не отправляется заказчику; эта проверка подтверждает UI-переход, а не исправление известного серверного блокера.

На итоговой мобильной версии прошли 33 проверки ui-review, 14 browser-smoke и 15 unit/DOM-тестов. Docker собран и запущен. Мобильные снимки фиксируют видимый экран, чтобы закреплённая навигация соответствовала реальному положению в окне.

Этот этап не закрывает серверную интеграционную приёмку; известные ошибки API остаются в отдельном запросе заказчику.

## Аналитический дашборд — 6 октября

Вместо длинной страницы таблиц — карточки общих показателей и три вкладки: «Обзор», «Навыки», «Данные». Добавлены 11 визуализаций: динамика сообщений, две тепловые карты, ритм недели, сравнение и доли групп, выданные/выполненные задания, интенсивность практики, распределение средних, освоение/охват и рейтинг навыков. Поиск, сортировка, подсказки и выбор ячеек позволяют разбирать показатели, не открывая исходные таблицы.

Цвета приглушённые; подписи поясняют показатель и область действия периода. Карта навыков сравнивает относительные значения, а полосы показывают абсолютные проценты. На телефоне графики занимают ширину контейнера; широкая карта и таблицы прокручиваются внутри блоков, нижняя навигация сохраняется. Нет записи отдельно обозначается как неизвестное значение.

Источник, формулы и ограничения каждого графика описаны в [admin-analytics.md](admin-analytics.md). Несоответствие дат выбранному периоду отображается явно; графики не обрезают серверные записи по предположению. Вопросы к заказчику остаются отложены по просьбе пользователя.

## Два 3D-рельефа

Четвёртая вкладка «3D» содержит календарную активность и распределение навыков по освоению/охвату. Поверхности расположены одна под другой на всю ширину, управление вынесено в видимые кнопки. Градиент от светло-синего до золотого показывает высоту; точки обозначают исходные значения, выбранная точка выделена золотым. Список под графиком позволяет найти дату или диапазон и прочитать точные числа без попадания пальцем в маленькую точку. У распределения раскрывается список навыков выбранной ячейки.

На телефоне поверхность изначально пропускает вертикальную прокрутку страницы. «Включить жесты» переводит её в управление: один палец вращает или перемещает камеру, два меняют масштаб и положение. «Завершить управление» возвращает прокрутку. Полный экран сразу включает управление; закрывается кнопкой или Escape. Вид сверху и сброс камеры помогают вернуть понятную ориентацию.

Пропуски календаря сохраняются разрывами, редкие данные показываются точками с пояснением. Рельеф навыков учитывает каждый навык один раз; интерполяция подписана как визуальная. Без WebGL показаны объяснение и точные данные. Выбранная вкладка сохраняется при смене периода. Проверка касаний выполняется в Chromium; физический телефон не проверялся.
