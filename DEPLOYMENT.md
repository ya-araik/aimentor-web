# Развёртывание для заказчика

## Что нужно

- Docker с командой `docker compose` (Compose v2). На Windows — Docker Desktop с Linux-контейнерами; на Linux — Docker Engine и Compose plugin.
- Доступ к Docker Hub и npm при первой сборке; доступ контейнера к существующему API при работе.
- Свободный порт для приложения. По умолчанию — 8080.

Node.js, npm, отдельный сервер приложения и база данных на машине развёртывания не нужны. Репозиторий содержит исходники, lock-файл зависимостей и Swagger для генерации типов.

## Первый запуск: один файл настроек

Из корня репозитория создать `.env` из `.env.example`:

Linux/macOS:

```sh
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Настройки:

```dotenv
API_UPSTREAM=http://ai-mentor.tw1.ru:8000
WEB_PORT=8080
```

| Переменная | Назначение |
| --- | --- |
| `API_UPSTREAM` | Полный адрес существующего API, доступный **из контейнера**. Обязателен; `http://` или `https://`, без адреса страницы Swagger (`/docs`, `/openapi.json`) и без клиентского префикса `/api`. В примере указан текущий сервер из контракта. Завершающий `/` допускается и убирается автоматически. |
| `WEB_PORT` | Порт на машине развёртывания. По умолчанию 8080; для прямого HTTP можно указать 80, если он свободен. |

Запустить:

```sh
docker compose up -d --build
```

Открыть `http://localhost:8080` на этой машине или `http://SERVER_IP:8080` с другой. Порт должен быть доступен через сетевой экран сервера. Приложение привязано ко всем сетевым интерфейсам; адрес и порт контейнера внутри Docker всегда остаются `web:80`.

Первый запуск включает установку зависимостей, генерацию типов из Swagger и production-сборку. Это выполняет Docker. Никаких дополнительных `.env`, конфигураций фронтенда или команд npm для запуска не нужно. Контейнер использует реальные данные; демонстрационный режим в поставку не включается.

## Где находится API

- **Другой сервер:** указать его URL, например `https://mentor-api.example.org`.
- **Та же машина, опубликованный порт API:** `http://host.docker.internal:8000`. Имя настроено в Compose для Docker Desktop и Linux. API должен принимать соединения с Docker-сети; сервис, слушающий только loopback хоста, в Linux может быть недоступен из контейнера.
- **Доступное DNS-имя во внешней Docker-сети:** использовать это имя можно, если контейнер фронтенда имеет доступ к этой сети. Стандартная поставка использует опубликованный порт или внешний URL и не требует правок Compose.

`localhost` / `127.0.0.1` в `API_UPSTREAM` означают сам контейнер фронтенда. Используйте их только если API действительно запущен в этом же контейнере (в данной поставке такого сервера нет).

Браузер обращается к `/api` на адресе фронтенда, Nginx проксирует запросы на `API_UPSTREAM`, убирая `/api`. Поэтому адрес API не вшит в JavaScript и меняется через `.env`. Отдельная настройка CORS для браузера в этой схеме не требуется. Имена пользователей и пароли в `.env` не нужны: пользователь входит в приложении в существующий API.

## Проверка запуска

```sh
docker compose ps
docker compose logs --tail=100 web
```

У `web` должно быть состояние `Up` и затем `healthy`. Проверка состояния обращается к `/healthz` внутри контейнера; она проверяет фронтенд/Nginx, доступность API проверяется отдельно.

Через браузер или curl:

```sh
curl http://localhost:8080/healthz
curl http://localhost:8080/api/groups
```

Первый ответ — `ok`, второй — JSON учебных групп от API. Можно также открыть регистрацию: список групп должен загрузиться. Авторизация и права пользователей остаются на стороне API.

## Обновление, перезапуск и остановка

После получения новой версии исходников:

```sh
docker compose up -d --build
```

После изменения только `.env`:

```sh
docker compose up -d
```

Compose пересоздаст контейнер с новой конфигурацией. Одного `docker compose restart` недостаточно для применения новых переменных. Изменённый порт подставить и в URL проверки.

Остановить:

```sh
docker compose down
```

Контейнер автоматически запускается после перезагрузки Docker/сервера, пока он не остановлен вручную. Логи ограничены тремя файлами по 10 MB. В этом репозитории нет базы/пользовательских файлов для резервного копирования; их хранит существующий API. `.env` с адресами окружения хранить отдельно от Git.

## Если запуск не работает

| Симптом | Что проверить |
| --- | --- |
| `API_UPSTREAM` не задан | Создать корневой `.env` из примера, указать полный URL и повторить запуск. |
| `port is already allocated` | Изменить `WEB_PORT` на свободный порт в `.env`, повторить запуск. |
| Фронтенд открывается, `/api/groups` возвращает 502/504 | Проверить URL, доступ API из Docker-сети и порт; посмотреть логи. Не использовать `localhost` для сервера на хосте. |
| API возвращает 500 | Запрос дошёл до API; проверять его серверные логи. Замечания к API временно отложены, список находится в project-plan/customer-api-requirements.md. |
| Сборка не может скачать пакеты/образы | Проверить доступ Docker к Docker Hub и npm, DNS и свободное место на диске. |
| Порт доступен на сервере, но не извне | Проверить сетевой экран и публикацию указанного порта. |

Для домена с HTTPS можно использовать существующий обратный прокси заказчика перед опубликованным портом. Эта поставка запускает HTTP на `WEB_PORT`; сертификаты и DNS относятся к окружению заказчика, в исходниках менять ничего не требуется.

## Что передать

Передать репозиторий с `.env.example`, `compose.yaml`, `web/`, `project-plan/contracts/` и остальными документами. Локальный `.env`, `web/.env.local`, `.local` с тестовыми доступами, `node_modules` и `dist` исключены из Git и Docker-контекста. Заказчик создаёт свой `.env` и запускает Docker по инструкции выше.

Подробности механизма `.env`: [Docker Compose interpolation](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/).
